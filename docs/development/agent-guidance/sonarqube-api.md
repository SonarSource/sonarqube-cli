# SonarQube APIs and network boundaries

- `SonarHttpClient` owns authenticated headers, timeouts, bodies, and HTTP-to-result conversion. New endpoints belong in domain clients taking this transport, never `(serverUrl, token)` constructors. Use `apiHostFor()` for regional API hosts. Empty successful GETs resolve to `undefined`; type bodyless endpoints accordingly.
- Obtain the transport from `ctx.connection` or `await ctx.resolveConnection()`. Helpers take a `SonarConnection` so auth/organization and transport cannot diverge. Context-less auth/telemetry/framework code may construct and thread one explicitly.
- Shared clients live in `src/core/server/`; command-specific clients live beside consumers. Keep display shaping/domain derivation outside the API layer. Expose shared clients as readonly fields rather than forwarding every method. Add timeout parameters only for an actual caller's budget.
- Keep result handling behind `src/core/result.ts` (the only direct `neverthrow` importer); cross to exceptions using the existing boundary.
- Only `src/core/server/fetch.ts` calls runtime `fetch`. All requests resolve network configuration there: `fetchAuthenticated()` protects credential headers with manual same-origin or HTTP-to-HTTPS-upgrade redirects; `fetchAnonymous()` follows credential-free redirects and rejects credential headers. Resolve proxy/TLS/NO_PROXY independently per hop; ignore caller-supplied transport overrides. Invalid network config must fail rather than silently connect directly.
- Sentry, flag evaluations, and future outward SDK traffic must use that path or equivalent proxy/TLS/credential protection. Do not initialize SDK background event/diagnostic/streaming transports that bypass it.
- For tests using invocation contexts, inject `createCliRuntime({ httpClientFactory })`. Context-less paths retain their existing transport seam. Direct flush tests must mock transport; read [test guidance](../../../tests/AGENTS.md) for telemetry isolation.
