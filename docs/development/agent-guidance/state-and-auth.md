# State, authentication, and project discovery

- `state-manager.ts` owns state. `loadState()` defaults only for an absent file; unreadable/invalid existing state retries then throws. Best-effort callers use `tryLoadState()`. Never turn a read failure into a default state that a writer could overwrite.
- Write only through `updateState()`: its synchronous callback runs against latest state under a SQLite immediate-transaction lock, followed by fsync/atomic replacement. Finish network/install work before entering the callback; merge feature changes by identity/target rather than overwriting a stale snapshot. Callback/lock errors must preserve prior state.
- Tokens and sensitive config belong in the keychain. Match normalized server URLs, including port/base path, before reusing credentials: keychain hostname accounts alone cannot distinguish servers. Env-var auth overrides saved login and must never write connections or keychain credentials. Use the invocation's memoized resolver; connection recording is for explicit login/org changes.
- Treat committed `.sonar-config.json` as untrusted. Resolve paths through containment checks, require existing directories, reject escaping symlinks/absolute paths and line breaks in project keys/paths. Preserve unrelated fields on writes and fail closed on unreadable/invalid existing JSON.
- Keep `targetRoot` distinct from `repoRoot` in known mappings; preserve recorded connection metadata rather than borrowing the current environment. Preserve conflicting project candidates and mappings absent from a fresh pass. Use shared lookup-path/recorded-feature resolution for worktrees.
- Discover through `discoverProject()` for an unambiguous complete binding, or `discoverProjects()` for multiple projects. Do not manufacture a project's server from unrelated active auth. Use `groupByMapping()` for nearest-root file assignment and `focusedOn()` for invocation scope; deleted files still need lexical mapping. Resolve auth before authenticated remote discovery.
- Preserve migration order: keychain moves before auth-dependent migrations; known mappings before reconciliation loses per-project attrs; consent before Sentry initialization. See [update guidance](../../../src/core/update/AGENTS.md).
- Reuse constants from `src/core/config-constants.ts`. Keep CLI data beneath the CLI-specific Sonar directory. Distinguish caller-agent detection from installed-agent discovery.
- On Cloud, validate organization membership and fail closed on membership-check errors. Generated tokens from failed login must be revoked; do not revoke reused or pasted tokens. Logout revocation is best-effort and must still clear local credentials.
