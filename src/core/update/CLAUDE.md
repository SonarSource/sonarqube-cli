# Self-update lifecycle

The self-update lifecycle lives under `src/core/update/` — a top-level peer of `core/host/` and `core/framework/`, not nested inside either, because it legitimately depends on both: `check.ts`/`notification.ts` (version check and the post-command update notice), `post-update.ts` (the orchestrator run once per upgrade from `src/index.ts`), and four single-purpose migration modules `post-update.ts` calls in sequence — `telemetry-migration.ts`, `known-project-mappings-migration.ts`, `claude-hooks-migration.ts`, `binary-refresh.ts`. `post-update.ts` also defines `migrateDeclarativeIntegrations` directly (not worth its own file — it's a 4-line load/save wrapper) around `reconcileInstalledIntegrations` (`src/core/framework/features/reconcile.ts`), which owns the actual replay-declared-features-against-recorded-state logic — kept in framework rather than host/update so nothing under `core/host/` ever needs to import from `core/framework/`. See "known-server-project-mappings" in `.claude/rules/state-and-auth.md` for why `known-project-mappings-migration.ts` must run before `migrateDeclarativeIntegrations`.
